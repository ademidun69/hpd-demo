Smart Contract Security Skill

Detect honeypots, rug pulls, and malicious contracts before your agent interacts with them.

Honeypot Detector (HPD) is a SKILL.md-compatible package that gives any AI agent the ability to evaluate the risk of an EVM smart contract. It returns a normalized 0–100 risk score and a clear verdict, with a fully traceable list of findings.

    What it analyzes

    Three layers of analysis, one clean verdict

    Static analysis

    Scans deployed bytecode for 30+ known-dangerous function selectors: hidden mint, blacklist, pause, owner withdraw, fee manipulation, proxy upgrade, selfdestruct.

    Behavioral simulation

    Forks Pharos locally via Anvil, deploys a copy of the contract, and runs a buy + sell round-trip to detect runtime traps that static analysis can miss.

    Reputation & context

    Inspects contract age, deployer, holder concentration, and liquidity lock status to surface contextual risk that pure code analysis cannot see.

    How an agent uses it

    Drop-in for any SKILL.md-compatible agent

    HPD is installed as a normal agent skill. The agent reads SKILL.md, identifies the right function, and calls it via the local CLI or library entry point.

    Install
    git clone https://github.com/ademidun69/HPD.git
cd HPD
npm install
export PHAROS_MAINNET_RPC="https://your-pharos-rpc"
    Agent prompt (natural language)
    "Analyze the contract at 0x51e2A2...BE29
on Pharos mainnet (chain 1672) and
tell me if it is safe to swap into."
    Programmatic call
    const hpd = require("./src/index");

const report = await hpd.analyzeContract(
  "0x51e2A2...BE29",
  { network: "pharos-mainnet" }
);

console.log(report.riskScore, report.verdict);
console.log(report.findings);
    Direct CLI
    # Full analysis
node src/cli.js analyze 0x51e2A2...BE29

# Static-only (no fork)
node src/cli.js quick 0x51e2A2...BE29

# On the testnet
node src/cli.js analyze 0x51e2A2...BE29 \
  --network=pharos-testnet
    Safety & scope

    Read-only by design

    HPD performs analysis only. It does not request wallet signatures, does not broadcast transactions, and does not connect to user wallets. All simulations run inside an ephemeral local Anvil fork.
